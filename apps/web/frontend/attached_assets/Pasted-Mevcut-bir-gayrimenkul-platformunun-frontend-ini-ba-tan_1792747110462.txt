Mevcut bir gayrimenkul platformunun frontend’ini baştan sona tasarlayıp geliştirmeni istiyorum.

Bu görevde backend’i yeniden tasarlamayacaksın.

Sana üç adet authoritative entegrasyon dosyası vereceğim:

```text
docs/
├── frontend-integration.md
├── api-endpoints.md
└── frontend-types.ts
```

Bu üç dosya, mevcut backend’in gerçek sözleşmesidir.

Frontend’i bu dosyalardaki endpoint, request, response, enum, authentication, pagination, upload ve veri tipi sözleşmelerine birebir uygun geliştir.

## EN KRİTİK KURAL

Backend’i frontend’e uydurmaya çalışma.

Frontend’i mevcut backend’e uydur.

Şunları ASLA yapma:

- olmayan endpoint uydurma
- endpoint path değiştirme
- request field uydurma
- response field uydurma
- enum değeri uydurma
- backend response tipini değiştirmiş gibi davranma
- mock API’yi gerçek entegrasyon yerine kullanma
- price veya decimal alanlarını backend number döndürüyormuş gibi varsayma
- refresh token’ı localStorage’a koyma
- backend’de olmayan “featured”, “popular”, “recommended” API’leri varmış gibi davranma

Bir bilgi bu üç dosyada yoksa önce bunu eksik kabul et.

Kendi varsayımını backend gerçeği gibi kullanma.

# 19. 401 REFRESH FLOW

Authenticated request:

```text
request
↓
401
↓
refresh attempt
↓
new accessToken
↓
request retry once
```

Refresh 401:

```text
logout state
```

Infinite loop oluşturma.

Aynı anda çok sayıda request 401 alırsa mümkünse tek refresh promise yaklaşımı kullan.

# 47. API URL / FILE URL

Bu kritik.

`NEXT_PUBLIC_API_URL`:

```text
http://localhost:3001/api/v1
```

olabilir.

Ancak backend:

```text
/api/v1/files/<uuid>
```

şeklinde root-relative file path döndürüyor.

Bunu yanlışlıkla:

```text
http://localhost:3001/api/v1/api/v1/files/...
```

haline getirme.

API origin helper oluştur.

Örneğin concept:

```text
API_BASE = http://localhost:3001/api/v1
API_ORIGIN = http://localhost:3001
```

File URL:

```text
API_ORIGIN + filePath
```

olmalı.

Bu davranışı entegrasyon rehberinden doğrula.
